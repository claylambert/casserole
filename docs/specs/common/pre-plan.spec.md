# Aetheris Lexical Graph Engine & LCARS UI Framework: Complete Architectural Specification

## 1. Paradigm & Core Architecture

The **Aetheris Lexical Graph Engine** is a native, highly optimized 2D visualization layer rendered directly within the Java Swing (`Graphics2D`) client. It serves as a visual diagnostic and semantic mapping tool for the operator's agentic workflows. By visually decoupling the chronological execution timeline from the conceptual web of ideas, it allows operators to track how data, domain terminology, and AMWP SSH protocol commands propagate across the canvas.

To provide a pure, distraction-free analytical environment, the engine is wrapped in a custom **LCARS (Library Computer Access/Retrieval System)** aesthetic. ## 2. LCARS UI Framework (The Chrome)

The visual wrapper is built entirely from custom Swing components overriding standard look-and-feels, prioritizing anti-aliasing and strict geometric constraints.

### 2.1 Graphics Rendering Engine

* **Base Canvas Rendering:** Bypasses standard Swing drawing, utilizing `paintComponent(Graphics g)` cast to `Graphics2D`.
* **Anti-Aliasing & Rendering Hints:** Global hints (`KEY_ANTIALIASING`, `KEY_TEXT_ANTIALIASING`) guarantee razor-sharp text and smooth bezier curves for node perimeters and LCARS elbows against a pitch-black (`Color.BLACK`) background.
* **Color Palette (`LcarsColorPalette`):** A centralized singleton defining the strict TNG palette: Pale Yellow (`#FFCC99`), Tangerine (`#FF9900`), Periwinkle Blue (`#9999FF`), and Magenta (`#CC6699`). Gradients and drop shadows are strictly prohibited.
* **Typography:** Condensed sans-serif fonts (e.g., *Swiss 911 Ultra Compressed*, *Antonio*, or *Oswald*) rendered entirely in uppercase, aligned dynamically depending on the bounding box geometry.

### 2.2 Reusable Component Hierarchy

A modular, human-extensible widget library built on standard Swing containers:

* `AbstractLcarsWidget` (extends `JComponent`): The base node handling background painting, bounding boxes, LCARS font scaling, and base color application.
* `LcarsButton` (extends `AbstractLcarsWidget`): Reusable pill-shaped (using `RoundRectangle2D.Double`) or rectangular buttons. Supports dynamic palette shifting on `MouseEntered` and `MousePressed`.
* `LcarsElbowPanel` (extends `JPanel`): The signature curved framing component utilizing `Arc2D.Double` within a `Path2D`. Configurable for Top-Left, Top-Right, Bottom-Left, and Bottom-Right orientations.
* `LcarsDataCanvas` (extends `JPanel`): The viewport responsible for rendering the internal node structures, utilizing double-buffering to ensure smooth panning and zooming.

### 2.3 Developer Extensibility

* **Geometric Hooks:** Corner arc radii, border thicknesses, and padding are exposed via runtime setters for on-the-fly layout adjustments.
* **Event Delegation:** Custom `LcarsEvent` wrappers provide localized coordinate spaces for complex composite widgets, allowing specific quadrant-clicks to be isolated.
* **Overlays:** Every concrete widget exposes `protected void paintCustomOverlay(Graphics2D g2d)`. Developers can inherit from base widgets and inject telemetry graphs or sparklines directly onto LCARS buttons without corrupting the base geometry.

## 3. Dual-Layer Graph Data Model

The actual graph rendered within the `LcarsDataCanvas` operates on a strict dual-layer logic system to keep visual clutter at an absolute minimum.

### 3.1 Layer 1: The Chronological Spine (Binary Cell Nodes)

The foundational backbone of the graph. Represents the chronological history of the active agentic workflow.

* **Structure:** Linear or branching timeline of `Prompt -> Execution -> Response` units (Cells).
* **Execution Bound Tags:** Edges distinguish between Local Execution (H2 data operations, local Python scripts) and Cloud/Remote Execution (AMWP SSH protocol dispatches).
* **Visual Representation:** Rendered as dark grey rounded rectangles with bold LCARS-colored strokes along the central axis of the canvas.

### 3.2 Layer 2: The Semantic Constellation (Lexical Nodes)

Satellites that orbit the spine. These are extracted dictionary terms, regex matches, and domain concepts identified within the binary cells.

* **Extraction:** As cells are committed to the embedded H2 database, a background Lamina thread scans the payload against the active `LexicalDictionary`.
* **Connectivity:** A Lexical Node is drawn if its corresponding term appears in two or more Cell Nodes.
* **Visual Representation:** Rendered as clean, circular nodes with semi-transparent fills. Edges connecting Lexical Nodes to Cell Nodes are drawn using a `BasicStroke` with a `dash` array.
* **Active Data Flow Indication:** Edges can be animated utilizing a Swing `Timer` to increment the dash phase, visualizing the flow of context parsing across the canvas like a live engine schematic.

## 4. Visual Navigation & Scope Pruning

To handle the complexity of an evolving, multi-agent context window, the graph implements real-time layout recalculation and filtering.

### 4.1 Type-Ahead Filtering

* A high-contrast LCARS search band situated in the upper frame.
* **Behavior:** As the user types, the UI immediately prunes nodes not matching the substring. Unrelated cell nodes fade out (alpha composite manipulation in `Graphics2D`), pulling the matching conceptual clusters into the center of the viewport via spring-physics or animated tweening.

### 4.2 Five Core Layout Topologies

The `LcarsDataCanvas` supports dynamically swapping between distinct mathematical layout algorithms depending on the analytical goal:

1. **Chronological Spine:** Default view. Cells in a straight horizontal/vertical line, lexical nodes orbiting them.
2. **Force-Directed (Spring):** Purely semantic view. Cells gravitate toward shared lexical nodes, naturally forming clusters of related topics, ignoring chronological time.
3. **Radial:** A selected central concept (e.g., "H2 Database") is locked in the center, and all cells/terms referencing it radiate outward in concentric rings.
4. **Hierarchical (Tree):** Best for visualizing parent-child tool execution (e.g., a master prompt dispatching three parallel AMWP SSH tool calls).
5. **Circular / Chord Diagram:** All cell nodes form the outer perimeter; thick bezier curves crisscross the interior to show dense semantic overlap.
